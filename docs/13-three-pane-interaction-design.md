# 三栏工作台交互设计

当前实现以 [DSH 插件迁移](14-dsh-plugin-migration.md) 为准：已退役独立预览，通过 ORYH 根布局插件实现左菜单、中业务、右原生聊天；本页 AI 业务协作部分仍属于目标设计。

2026-09-08 · 设计与分阶段实施记录。依据客户端代码和用户提出的「左菜单、中业务页面、右聊天」要求。该交互原型已退役，实际实现见上方插件迁移说明。

本提案更新 docs/03-experience-design.md §2.1 中业务视图与会话互相替换的布局：二者同时存在，共同操作一个有明确企业与对象边界的任务。

## 1. 产品原则

左侧回答「去哪里」，中间回答「现在是什么、要改什么」，右侧回答「希望如何完成」。中间是可编辑、可核对的工作现场；AI 与用户操作同一个草稿或查询状态；ORYH 返回的记录是正式业务事实。

没有 AI 时，菜单、列表、筛选、详情、表单、校验和正式操作仍完整可用。有 AI 时，用户减少重复输入、筛选组合与材料阅读。AI 可暂停、失败或关闭，不应阻塞手工工作。

## 2. 当前问题与调整

- app.tsx 左侧菜单与中间直接操作卡重复；菜单点击目前直接运行查询，应改为切换有独立状态的业务页面。
- ExpensePanel 常驻所有业务结果上方，应归属费用申请模块；列表、新建、详情之间有返回路径。
- 右侧目前是已保存操作和连接管理；已保存内容归入对应模块的保存视图，连接和外观归入设置。
- 页面主要显示企业名和实现机制说明；改为业务标题、筛选与操作。企业/账号/测试环境标识保持在全局栏。
- 表单在组件内维护状态；接入聊天前需要建立共享草稿状态和有版本的变更协议，避免让模型直接操纵输入框。
- 现有 expenseConfirm 与 AI 工具分离、服务端校验和结果待核对机制应保留。

## 3. 布局与导航

桌面初始尺寸建议：左侧 208–224px，右侧 360–400px，中间占剩余宽度。左右可收起，聊天可拖动宽度；保证中间基本可读宽度，不足时聊天改为抽屉。约 1440px 窗口可采用 216 / 824 / 400。尺寸是初始设计参数，须用真实表格与表单验证。

全局栏：企业切换、明确的「测试环境」、连接状态、当前用户。左栏底部：设置、打开 ORYH Console。不会因页面滚动而失去企业边界。

首版菜单只出现可用能力：我的待办、费用申请、项目。费用页面内设「申请列表 / 本地草稿」；已保存查询放在所属模块。未来新增审批、采购等模块应按服务端能力和权限展示，不能提前提供空壳菜单。

中间列表页：面包屑/标题 → 主操作（如新建）→ 搜索与结构化筛选 → 当前条件 → 表格 → 分页/结果范围/刷新时间。选中行打开中间详情页，返回列表恢复条件、页码、选中项和滚动位置。

中间表单页：标题/草稿状态 → 基本信息 → 明细 → 附件 → 校验提示 → 固定底部操作区。详情较长时提供页内分组导航。业务表单不占用右侧抽屉，避免与聊天争夺位置。

三栏各自滚动，列表工具栏和聊天输入区固定。表格可以局部横向滚动，整个页面不横向溢出。窄屏默认业务页面，聊天以可返回的全屏面板展示；关闭面板保留草稿、会话及焦点。拖动和折叠均提供键盘替代操作。

视觉采用紧凑的企业应用风格：浅中性色、单一强调色、清楚的分隔、稳定的表格行高与数字对齐。避免巨型企业标题、大量功能卡与装饰占用工作空间。沿用 React / Fluent UI，无需换框架。

## 4. 聊天上下文

右侧顶部始终显示当前任务，例如「协助：费用草稿 · 客户拜访」。可展开查看本次使用的页面、对象、选中记录、附件和查询范围。整个会话不可跨企业复用。

上下文分为两层：当前任务绑定的对象/草稿，以及每次发送时截取的页面状态。聊天历史不是当前数据快照，每次动作都重新校验身份、对象与版本。

- 同一任务的列表到详情可携带明确的选中对象；涉及另一单据或另一模块时，切换到对应任务会话，并保留旧会话供恢复。
- 未选记录时，「这些」指当前查询范围还是当前页必须明确；批量操作必须显示具体范围及数量，不能默认为整库。
- 对未保存草稿导航离开前先尝试本地加密保存；保存失败时给出留在页面/重试/明确放弃。不得静默丢弃。
- 页面切换时，旧任务正在生成的建议留在原任务，不能落到新页面。跨模块请求先给导航动作；涉及未保存修改时遵循相同保护。
- 仅向模型传递完成本次请求所需的字段。模型发送边界按企业策略落实；票据上传 ORYH 与发送外部模型是两个不同动作。
- 附件与业务文本属于数据，不能修改权限、工具目录或执行规则。

## 5. 用聊天填写表单

示例：「帮我填一笔昨天拜访客户的交通费，出租车 86 元。」

1. 明确定位当前费用草稿；如果没有，则在中间打开新草稿。相对日期按企业/用户时区解析，并显示具体日期。
2. AI 生成结构化字段变更：业务日期、费用分类候选、金额、说明。员工、企业、审批状态由系统绑定，不能来自模型。
3. 明确无歧义且没有冲突的内容可以直接填入本地草稿。中间高亮改动字段并标记「AI 填写」；右侧简述改动数量，提供查看改动和撤销本次填写。
4. 金额、币种、对象关联或票据识别存在歧义时，显示候选/待核对值，不猜测后作为确定值使用。必填缺失在字段旁提示，聊天一次优先询问最影响下一步的问题。
5. 用户可随时手改。AI 请求携带基准版本；响应返回时按字段检查冲突，只应用仍适用的变更。用户请求之后改过的字段不得覆盖。明细使用稳定行 ID，不能仅依赖数组下标。
6. 撤销只撤销本次 AI 变更且未再被改动的字段；遇到后续修改显示冲突选择。不能用旧快照覆盖整个表单。
7. 正式创建/提交前，将全部待核对项集中展示，并走现有服务端校验和有版本的确认。修改后旧确认立即失效。

解释、建议、草稿变更、服务端执行回执四种聊天消息必须可辨。不要逐 token 更新输入字段；完整字段变更校验通过后一次应用，避免焦点跳动。

## 6. 用聊天组合查询

示例：「查上个月我提交的、金额大于 1000 元且还没审批完成的费用，按金额从高到低。」

AI 将语言转为受支持的查询条件；中间同步展示具体日期、申请人、状态集合、金额阈值和排序。模糊的业务词需映射到真实状态定义；无法确定时先澄清。

用户可以直接删除条件、调整筛选；接下来「只看交通费」默认在当前查询上追加，而「重新查全部」清除哪些条件需要明确反馈。提供撤销本次筛选、重置和保存视图。

只读且条件明确的查询可自动运行，无需每轮确认。模型不生成任意 SQL/API；服务端执行登记的查询能力。不支持的筛选应明确说明，不得假装生效，也不能只筛当前页却宣称查询了全部数据。

聊天总结必须引用此次结果及其时间、覆盖范围。查询尚未完成时旧结果保留并标记更新中；失败时旧结果标记非最新。分页列表的当前页合计不能冒充全量合计，多币种不能直接相加。用户修改条件后，历史总结保留原有条件标识。

保存视图保存条件及排序，不固定当时的数据。重新打开执行真实查询，不调用模型。

## 7. 动作风险与反馈

| 动作 | 默认交互 | 事实边界 |
|---|---|---|
| 解释、受权只读查询 | 直接执行，显示范围与来源 | 不写业务记录 |
| 填写本地草稿、调整筛选 | 无冲突则应用，能撤销 | 明示尚未写入 ORYH |
| 上传附件 | 独立展示上传状态和目的地 | 上传可能已产生服务端记录，不能称为纯本地 |
| 创建/提交业务记录 | 服务端校验后，统一正式确认区 | 明示企业、对象、金额与动作后果 |
| 审批、批量修改等未来能力 | 按动作定义确认，展示目标范围和规则 | 后端权限、校验和审计不可缺失 |

用户在聊天说「提交」可进入准备与核对流程；最终确认按钮触发受控执行，模型不能调用确认接口。聊天与表单入口汇入同一份确认内容，避免两套核对与重复弹窗。

保留当前创建与提交两个服务端阶段，在界面上清楚说明「创建后尚未提交」。是否未来合为一次用户确认，必须先有能承接部分成功、幂等与版本保护的服务端流程，不能仅隐藏中间状态。

成功来自服务端回执，展示记录编号、实际状态与查看入口。超时显示「结果待核对」，提供读取核对，不提供可能重复执行的盲目重试。「停止 AI」只能取消推理/尚未发出的动作，不能声称撤回已发送的写请求。

模型失败只影响右侧；表单输入、已应用修改和查询条件保留，用户继续手工操作。权限变化、企业切换、对象版本变化令待执行动作失效。技术错误翻译为可操作的中文说明，诊断细节折叠。

## 8. 实现边界与顺序

共享任务状态至少包含企业/用户范围、页面类型、对象或本地草稿 ID、草稿版本、字段来源与修改记录、结构化查询、结果快照、待确认动作。页面与聊天使用相同的校验器和业务命令。

AI 工具只获得受控的页面上下文读取、字段变更建议、查询条件设置、业务读取和准备动作；凭据、任意网络访问与正式确认不作为工具暴露。后台再次检查所有边界，不能仅依赖按钮是否禁用。

实施顺序：

1. 重建三栏壳、模块路由、列表/详情/表单，迁移已有功能。未接入模型时聊天明确提示尚未连接，不用假回复伪装可用。
2. 抽出共享任务状态、版本化字段变更和结构化查询协议，完成冲突/撤销/上下文隔离。
3. 接入受管 DSH，对费用草稿填写和已支持的费用查询形成真实闭环；按 ORYH 能力补查询字段，不在 UI 宣称尚不支持的筛选。
4. 再扩展票据识别、其他业务对象和多步任务，不先铺大量不能执行的菜单。

验收重点：关闭聊天仍能完成原流程；一句话填写后可手改和撤销；AI 慢响应不覆盖手改；筛选双向同步且不误报范围；导航不会串单；写入仅由受控确认触发；超时不会重放；窄屏与键盘操作完整。

## 9. 当前插件实施记录

三栏已迁移至正式 DSH Profile：ORYH 根布局插件渲染业务菜单、中间根级业务 Slot 和右侧原生 conversation；官方侧栏、模型设置及 Session 服务保留。没有独立页面服务器或模拟聊天。桌面聊天可收起；窄屏切换业务／聊天并保留挂载状态。当前没有拖动调整列宽。

BusinessPage 提供待办／费用／项目列表、只作用于已载入批次的组合筛选、分页及详情。费用表单支持本地草稿、版本化确认与待核对恢复。切换菜单及聊天视图不卸载未保存表单；离开表单仍有保存／放弃确认，未保存修改阻止切换企业。

右侧是 Harness 原生会话，没有自动填写或自然语言业务查询。企业绑定 Session、可撤销字段变更和业务工具协议仍待完成。当前 Agent 工具被开发策略限制，界面明确标注业务 AI 联动尚未启用。

`pnpm verify` 的构建、类型检查和 57 项测试通过。Chrome 验证桌面三栏、真实待办与费用类别读取及表单保留；应用内浏览器验证 390px 视图切换、可展开菜单和离开确认。未保存测试输入已清理，未创建或提交远端费用申请。布局热替换限制及手动更新方式见迁移文档。
