# 业务页面设计与工时整单编辑

2026-09-12

## 架构边界

沿用 ADR-0008：`@oryh/dsh-host`、`@oryh/dsh-client` 两个 Harness 插件，领域保持为库。未新增独立页面服务器、应用框架或 Harness 私有源码依赖。会话、主题、模型与批准能力仍由 Harness 提供；本次只调整业务 Slot 内的视图和共享工时操作。

## 设计约定

- 标题与主要操作在页首；查询控件、显示配置、表格、空态和分页在同一列表面板内。
- 打开一行、返回、刷新、新建、状态、条数与分页、空态、时间格式等共享表达的统一写法见[业务页面表达约定](25-ui-conventions.md)（2026-09-13）。
- 待办、项目、费用、工时、销售订单、库存、收发货共享标题层级、字号、边框、行高、表格间距和交互色。
- 筛选栏与列配置仍沿用现有偏好存储，不更改用户已配置的列。
- 浅色与深色使用已有主题映射。样式限定在 ORYH 业务根节点内，不覆盖 Harness Chat。
- 工时表单分基本信息、明细、固定在可视区底部的合计与保存操作栏。宽栏显示一行明细，普通栏采用两行，窄栏进一步重排，保证输入控件可用。

## 工时交互

新建与可编辑的现有单据共用 `TimesheetEditor`。每条明细可以修改日期、工时、类型、项目、任务和备注；添加、删除、撤销最近一次删除均只改变本地草稿。允许先删空再新增，空明细不能保存。

一次“核对并保存”展示整单内容，正式确认后才写服务端。保存和提交审批仍是两个独立操作。保存成功重新读取该单据；失败或结果不确定保留当前输入。返回列表时如有未保存修改，可选择继续编辑或放弃。

Chat 的 `update` 建议携带完整 `fields`，已有明细保留 `id`，新增明细不传编号，删除明细从数组移除。手工与 Chat 共用草稿；建议不持有确认 token、不写业务服务。旧的逐行建议在页面应用时也只修改当前整单草稿。

## 后端依赖与兼容

配套改动位于 `/Users/wtong/git/calwbiz`：

- `GET /api/v1/timesheet-headers/{id}/detail` 增加整个单据的 `revision`。
- `POST /api/v1/timesheet-headers/{id}/save` 接收 `expected_revision`、`intent_id`、期间、说明及完整明细。
- `?validate_only=true` 执行相同检查并回滚，返回 `meta.validate_only=true, written=false`。
- 已有明细按编号更新并保留未编辑元数据；遗漏编号对应软删除，新明细新增；所有操作及审计记录在一个事务内提交。
- 校验权限、员工归属、可编辑状态、期间、每日合计、明细归属与重复编号。版本不匹配返回 409；后端共享父单据锁串行化本模块的整单与旧逐行写入。
- Header 的 `oryh_client_save_intent_id` 用于写入结果不确定时查证，不自动重试写入。

**测试环境尚未部署这项后端改动。** 新建整单保存继续使用原接口；编辑现有工时可在页面操作，但旧服务没有 revision 时会在预校验前明确提示升级，并保留草稿，不会偷偷降级为多次逐行写入。部署顺序应为 ORYH 后端、再客户端；不需要数据库 schema 迁移。

## 验证范围

- 客户端构建、类型检查及全量单元/交互测试。
- 工时领域：预校验无正式写入、确认后单次整单请求、旧服务和过期版本拒绝。
- 页面：添加、删除、撤销、失败保留、原单恢复、现有单据只读/编辑模式。
- Chat：完整草稿建议、已有编号保留、拒绝外部或重复编号，建议不触发确认接口。
- 后端：整单修改/添加/删除、dry-run 回滚、坏行回滚、过期版本、重复/外部编号、每日超额、不可编辑状态。
- 真实 Harness 浏览器检查工时、业务列表、浅色/深色、拖动分栏。未在测试环境执行真实业务保存或审批。

PostgreSQL 并发压测和测试环境真实保存验收留给后端部署阶段；本地事务测试使用仓库的隔离 SQLite 测试工厂。
