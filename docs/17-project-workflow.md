# 项目新建插件

在原生 Chat 中说“新建项目”，或在项目列表点击“新建项目”，打开同一业务表单。Chat 可以填写项目名称、编码、客户、开始日期和结束日期；未指定修改的字段保持原值。名称必填，编码留空时在核对阶段生成，新项目状态为进行中。

实现沿用公开 Tools、Session、Slot/store 和生成的认证 Remote。`oryh_open_project` 等待页面打开回执，`oryh_project_read` 读取字段、版本和实际权限，`oryh_project_fill` 通过版本校验更新未保存字段并等待页面确认。正式创建入口不注册为模型工具。

传统表单的“核对并创建”执行本地校验、权限复核和编码冲突查询，并生成加密保存的短时确认记录；确认对话框中的“确认创建”才调用 ORYH `POST /projects`。服务端没有 dry-run 接口，因此核对阶段不能保证最终创建成功，最终结果以服务端回执为准。权限遵循后端的 `master_data.manage` 或兼容的 `users.manage` 授权，租户和用户来自已验证连接。

创建前先持久化执行状态，确认凭据单次消费，防止同一确认重复提交。网络中断、回执不完整等情况标为结果未知；“核对服务端结果”只查询，不重发创建。匹配项目编码、字段和本次操作的 metadata 标记后才确认成功。未知结果未解决时阻止准备新的创建。执行记录按企业、租户和用户隔离，并复用加密修订存储机制。

验证：构建及 117 项测试通过，覆盖权限、字段校验、确认前无写入、重复确认、回执丢失后核对、过期与冲突、Chat 版本与人工修改冲突，以及表单确认流程。真实浏览器验证 Chat 打开和填写、传统按钮入口；未执行测试环境的正式创建。

当前页面上下文按 Session 绑定。同一 Session 同时在多个窗口操作时，最新同步的窗口可能接收填写；业务操作应在一个窗口内完成。项目编辑、归档和删除不在本次新建能力范围内。
