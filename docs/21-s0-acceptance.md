# S0（P0）工作包验收标准

更新：2026-09-14。审阅基线：ORYH AI Client `48748eb`；实际执行时锁定 Client、ORYH、Harness、依赖、镜像与补丁版本。

状态：验收标准；部分本地测试及合成身份 Docker 隔离探针已执行，真实 OAuth、业务写入与完整浏览器验收尚未完成。逐项进展见[实施记录](27-server-p0-implementation.md)及[部署状态](31-server-deployment-status.md)，不能将本文件的标准当作全部已通过。对应[多租户服务器版实施方案](19-multi-tenant-server-plan.md)。

P0 用最小原型检验关键契约，避免未经验证就建设完整控制层。每项要求可重复的观测和明确退出条件；模型声称“已拒绝”、首页能打开、Mock 成功均不足以证明服务器版可行。

## 顺序与证据要求

```
S0-0 可复现构建与公开扩展点
  ├─ S0-1 原生前端、代理与浏览器隔离
  ├─ S0-2 每身份执行容器、生命周期与限额
  ├─ S0-3 OAuth → 技能 → 委托身份契约
  ├─ S0-4 外部凭据代理与主动泄漏测试
  └─ S0-5 可信确认、幂等恢复、技能版本与同步
```

- S0-3/4 的 ORYH 契约最早启动；S0-0 是有效运行证据的门槛。接口确认和测试设计可先准备。
- 先贯通一个身份的真实登录、技能获取、查询、确认写入及撤权，再用四身份验证并发和隔离。S0-1/2 可先用合成身份、测试代理搭建原型。
- 六项全部通过才进入 P1。外部依赖未完成时可以继续独立原型，但不能用 Mock 替代真实联调，也不能批量实施依赖未定契约的功能。
- 真实写入只在独立测试 tenant、明确授权的测试对象范围内进行。泄漏测试使用可撤销的合成 canary 凭据，不读取真实用户安装目录或把生产凭据写入报告。
- 每项产出记录：负责人、日期、锁定版本、配置 hash、测试身份、步骤、脱敏证据、通过/失败/未验证、外部依赖及下一步。缺少证据视为未验证。

## S0-0 可复现构建与公开扩展点

### 步骤

1. 在干净目录克隆并锁定 Client 与 Harness，按 README 安装、应用所需补丁、构建、verify、安装 Profile 和启动；不使用已有全局产物。
2. 记录 Node/pnpm、提交、依赖闭包、镜像及补丁 hash，重复构建并比较生成声明/描述符。
3. 从本次锁定版本生成 Remote、流式入口、文件/模型/插件/Workspace 管理能力清单，逐项标记允许、受控、禁用。不沿用旧版“2 流式、86 普通”的固定数字。
4. 读取 resolved Profile，验证真实插件生命周期、Remote 描述符、浏览器 composition；核实业务视图和原生 Chat/Composer/Session 复用。
5. 检查公开 approval、Shell/jobs、模型连接与生命周期扩展点。源码阅读只证明候选能力存在，组合可行性仍由 S0-2/4/5 原型证明。

### 成功判据

- 干净环境只用已记录步骤即可进入工作台；所有要求的构建/补丁检查通过。
- 相同输入的生成接口产物一致；变化有显式清单评审，不以数量相等代替接口一致。
- 无产品代码对 Harness 私有源码的依赖，无第二套聊天/Session/应用框架。
- 现有生成器补丁如仍需要，有锁定版本、实际执行产物的守卫、责任人和上游/维护安排。

### 停止条件与产出

缺少可复现步骤、补丁失配或必需能力只能依赖私有实现时，先解决后重跑。产出构建锁定清单、Profile/接口暴露清单、公开能力与缺口表；不要求自动创建定时任务。

## S0-1 原生前端、认证代理与浏览器隔离

### 步骤

1. 分别验证路径前缀和受控子域，记录入口 HTML、boot manifest、插件 bundle、静态资源、REST、Remote mux、WebSocket、流式 Remote、下载、Cookie、Location 和深链刷新。
2. 逐项标记原生通过、仅需有界代理配置、需私有修改。不要预设一定要改写 HTML，也不以首页成功推断其他路径通过。
3. 用选定方案同时接入至少两个 owner：前缀方案验证同 origin 下 Cookie/路由不互相覆盖；子域方案验证 host-only Cookie、DNS、TLS 与一次性引导票据，不能要求子域还必须同 origin。
4. 测试断网重连、过期登录、撤权、跨 owner 句柄、导出和取消。恢复的是连接和持久历史，不承诺接续被终止的模型推理。
5. 用测试 HTML/SVG 附件尝试读取应用凭据、访问父页或调用另一 owner API，验证独立附件源/下载策略/预览沙箱。

### 成功判据

- 选定方案所有必需面通过；每次请求与长连接均有 owner 校验，没有公开 runtime 内部地址或启动凭据。
- 多标签页企业切换不影响另一标签页，直接 API 调用也无法越权。
- 活跃附件不在应用可信源执行，下载链接不能绕过授权。
- 同源/跨源策略与代理选择相符，子域成本和部署前提明确。

### 停止条件与产出

任一必需面只能靠持续修改私有实现，或附件能取得应用权限，停止并修订组合。产出认证代理 ADR、可复现配置、接口结果表和浏览器隔离证据。

## S0-2 执行容器、生命周期与资源限额

按 [ADR-0011](adr/0011-server-trusted-host-and-isolated-shell.md)，默认每 owner 有可信 Harness Host 和独立脚本执行容器；Host 不与租户 Bash 共享执行信任域。不同 uid、独立 HOME 和 Harness 沙箱都是需要组合验证的措施，不能单独作为强隔离证明；也不预设 rootless 必然需要或不能使用某项 capability。

### 步骤

1. 建立 A1/A2（同 tenant）、B1（与 A1 同自然人、不同 tenant）、B3 四个测试身份，各自独立 HOME、技能、Session、数据卷和执行网络策略。
2. 从 A1 容器直接运行测试脚本，尝试读取其他 owner 的卷、进程、配置、临时文件，以及访问邻居 runtime、控制服务、metadata、编排和容器引擎接口。重复测试原生 Remote 的列举、读取、订阅、导出、取消及任意路径注册。
3. 篡改 manifest 持有人、请求头、tenant/user 参数、runtime 句柄，直接请求代理；测试不能依赖模型是否愿意执行攻击步骤。
4. 同时打开多个标签页、强杀 runtime、保留后台子进程、启动新 generation；尝试由旧任务继续发请求，并检查持久卷单写者和任务进程树清理。
5. 对 CPU、内存、PID、磁盘、工具时长、后台任务、网络与模型并发施压，观测限流/排队及其他身份最低可用性。
6. 固定目标服务器规格，按 4/10/20 活跃身份运行页面、流式 Chat、Bash 和混合负载；超预算立即停止加压。记录纯页面访问的底噪与容器启动成本。

### 成功判据

- 直接脚本和直接 API 均无法跨 owner 访问，错误不泄漏内容或资源存在性。
- 伪造身份/快照被可信层拒绝，不能取得其他身份委托；在 ORYH 的测试写入 actor 与真实 owner 一致。
- 同 owner 多标签页只启动一个 runtime；新代次生效后旧任务不能发送新请求，已发送结果另行核对。
- 活动工具/后台任务不会被误判为空闲；排空超时可终止完整进程树。
- 资源限制实际生效，有容量曲线和故障余量；不能从历史 macOS 单次 RSS 外推服务器承载数。

### 停止条件与产出

出现跨身份访问、旧代次继续发送新请求、编排权限暴露或无法控制资源耗尽，停止并加强隔离。必要时评估额外沙箱/虚拟机，不退回单容器共享权限方案。产出隔离报告、执行平台 ADR、生命周期证据和容量基线。

## S0-3 OAuth、技能获取与委托 actor 契约

ORYH main 已通过 MCP prompts/resources 提供无凭据技能，服务器不再依赖 ZIP。当前 Harness MCP 桥接仅支持 tools，需补齐技能消费与 OAuth 生命周期。ORYH 使用不透明访问令牌，不假设 OIDC 或 JWT。见 [MCP 复核](28-server-mcp-skills-review.md)。

### 步骤

1. 核实 ORYH 的 URL client_id、非 loopback 回调、state/PKCE、稳定身份字段及 tenant 绑定；当前没有动态注册和 membership 枚举契约，实际验证分别授权流程。
2. 使用同一 OAuth 主体完成 MCP initialize、tools/list、prompts/list/get、resources/list/read；验证 scope、actor、生命周期和按角色过滤。不给个人身份静默换管理员 key。
3. 单身份走完真实链路：登录 → MCP 取技能 → 经 S0-4 受控连接查询 → 经 S0-5 可信确认完成测试写入 → 核对 ORYH actor 与 requestId。
4. 测并发刷新、重复/过期回调、注销、角色变化、委托撤销、长连接仍打开和在途请求。
5. 区分本客户端注销和 ORYH 远端授权撤销（当前未公布 OAuth 撤销端点）；列出试点实际调用 API 的读取/写入权限、员工绑定、幂等/结果查询契约。只读角色直接发写入请求也必须被拒绝，不能仅检查技能目录。

### 成功判据

- 在正式服务器回调形态下完成完整链路，用户无需另行手填长期 key。
- Principal、membership、委托 actor 一致；刷新竞态不复活撤销授权。
- 撤权和缓存失效有明确测试时间上限，并验证新请求、现有连接及后台任务。
- 接口权限不足、不能核对/幂等的操作有明确排除范围和补齐责任，不宣称全部业务已支持。

### 停止条件与产出

部署不支持已存在的 OAuth/MCP 契约或身份联调失败时，记录具体差异并阻止进入 P1；不再要求先提供无凭据 ZIP 接口。产出接口契约、Principal 定义、tenant 切换交互、支持操作矩阵及撤权测试证据。

## S0-4 外部凭据代理与主动泄漏测试

默认外部代理注入真实凭据，执行区域只得到结果。文件、环境变量或可导出的无限制代理 token 不作为安全替代。工作负载身份不能由脚本自报，也不能允许脚本指定凭据目标。

### 步骤

1. 用合成 canary 为 ORYH、模型和控制服务设置各自测试凭据；真实凭据仅存可信区域，执行侧不挂载秘密。
2. 联合 S0-3 跑无凭据技能查询与确认写入，验证浏览器、可读配置、脚本均无需持有真实 key；MCP 认证仅位于可信连接侧，prompt/resource 与工具输出也做泄漏检查。
3. 在执行容器直接运行恶意测试脚本，遍历有权限的技能、配置、临时文件、环境和进程信息，尝试读取秘密或控制身份。
4. 测试认证头覆盖、其他 owner、过期 generation、任意目标、重定向、代理管理接口和直接出网绕过；验证模型端点同样受控。
5. 在受控测试环境捕获模型请求和工具输出，并检查 Session、导出、日志、诊断及恢复产物；检索 canary 时报告只记命中位置/数量，不打印凭据。

### 成功判据

- 无凭据技能可用，业务 actor 正确；模型和业务代理均按可信 owner 计量。
- canary 不出现在执行区域、模型请求、Session、浏览器和普通日志中。
- 同权限脚本不能读取凭据，也不能把代理变成任意目标/任意身份的开放转发器。
- 可信服务内的秘密存储及测试捕获文件有访问和保留控制；测试结束撤销 canary 并清理捕获。

### 停止条件与产出

任何真实凭据进入执行区域或可由脚本导出，停止并修订代理边界。MCP 技能必须由服务端无凭据渲染，不得以客户端事后遮盖替代；管理类工具返回凭据的操作必须拒绝向模型暴露。产出凭据契约、代理威胁模型、主动测试及脱敏检索报告。

## S0-5 可信确认、恢复、技能版本与同步

本项验证新增机制的最小可行性，不要求在 P0 完成全部领域适配。各类正式开放操作仍需在 P3/P4 逐项验收。

### 步骤

1. 用 Harness 公共 approval 能力在 Chat 内展示测试操作，让真实用户响应绑定 owner/Session/请求摘要/有效期；在执行区域外生成一次性授权。业务栏关闭时也能完成，不引入额外页面确认。
2. 直接脚本伪造“用户已同意”、修改载荷、换 Session、重复消费、过期后执行；尝试用通用 Bash 放行冒充业务批准。验证可信响应路径不能由 runtime 自行制造。
3. 对一个创建类和一个状态变更类测试操作注入故障：服务端已提交但丢失响应、代理写回执前崩溃、批量部分完成、同 operationId 并发、不同载荷复用 ID。核对 ORYH 最终记录，而非只看客户端提示。
4. MCP 目录/正文读取失败、并发刷新、任务中途内容变化和权限撤销；验证 owner 缓存隔离、内容 hash 和实际请求授权。当前接口没有跨读取原子 revision，不宣称快照一致。启用文件交付时另测下载中断、manifest/bundle 一致性和版本引用。
5. 两个 owner 模拟员工/经理，测试 Chat 提交、后台任务延迟完成、直接 ORYH 修改、事件丢失和页面重连；有脏表单时不覆盖。没有事件接口时用有界轮询，记录明确时限。

### 成功判据

| 面 | 判据 |
| --- | --- |
| 可信确认 | 模型和脚本不能签发/重放批准；载荷改变失效；用户在 Chat 确认一次，无业务页依赖 |
| 公开扩展 | 全链路使用公共能力；仅发现 approval 包或工具命令批准不算通过 |
| 幂等与未知结果 | 同操作不重复生效；批量逐项核对；无法确认结果保持待核对，不自动重发 |
| 服务端缺口 | 不支持幂等/查询的操作被明确限制，不能仅凭“先回读”承诺安全恢复 |
| 技能发布 | 中断不破坏上一版本，运行任务不读混合版本，旧技能不能延长已撤销权限 |
| 页面一致性 | 员工和经理有权页面在约定时限更新；其他 tenant 无泄漏；脏表单保留、冲突可见 |

### 停止条件与产出

可信确认只能靠模型自觉、只能改 Harness 私有实现、写入结果无法可靠区分或技能发布破坏运行任务时，停止相关架构并解决契约；不得降低保证后标记通过。产出服务器确认 ADR（明确相对 ADR-0010 的服务器补充）、操作恢复契约、技能版本协议和同步策略。

## 整体退出条件

六项全部通过，且以下决策有负责人、证据和未支持范围，才进入 P1：

1. 原生代理选型、Cookie/附件源及公开接口暴露策略。
2. 每身份执行容器、可信区域、网络策略、生命周期及资源限额。
3. OAuth 到无凭据技能和同身份业务委托的真实契约。
4. 外部凭据代理及模型配置，不可导出的身份绑定方式。
5. Chat 可信确认的公共扩展路径，以及幂等、结果核对和旧代次失效。
6. 原子技能版本、页面变更通知方式和可测的刷新/撤权时限。

P0 测试配置中的超时、预算与容量不是默认上线承诺，P5 在固定部署规格下重新确定。任一关键依赖升级、代理/执行形态变更、技能凭据协议变化后，重跑受影响项；不能永久沿用旧结果。

## 估算与后续工作包

P0 后按实际改造面评估 P1–P6；外部等待、上游公开支持与目标部署平台单列。S0 可以并行开展独立验证，但不是创建完整业务控制层的授权。阶段之间以验证结果推进，不以包创建完成或首页打开作为完成标准。
