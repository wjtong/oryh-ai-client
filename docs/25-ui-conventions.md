# 业务页面表达约定

2026-09-13。状态：已实施（分支 `ui-list-conventions`）。

起因是一个具体的不一致：「我的待办」列表行尾是一个“>”，点击进入详情；「我的工时」行尾是「打开」按钮；「工时审批」行尾又是「查看」。三种写法都能用，放在一起就像三个产品。按这个问题把 11 个菜单页面、详情页和表单逐一核对，同类问题远不止这一处。

## 1. 核对发现的问题

| 方面 | 之前各页面的写法 |
| --- | --- |
| 打开一行 | 行尾“>”图标；「打开」；「查看」；项目、记录列表、本地草稿没有行尾控件 |
| 条数 | 「筛选结果 N 条」；「共 N 条」；「N 条已载入」写在标题旁，页脚又写一遍 |
| 翻页 | 图标按钮（‹ ›）；文字按钮「上一页 / 下一页」 |
| 返回 | 图标按钮「返回列表」；文字「← 返回列表」；「← 返回项目列表」；页首右侧的「返回草稿列表」 |
| 刷新 | 图标＋「刷新」；只有文字「刷新」；「刷新草稿」 |
| 新建 | 有的主按钮带“＋”，有的不带 |
| 状态 | 状态胶囊；Fluent Badge（费用草稿、待办详情）；纯文本（项目）；英文原值（工时详情里的 `submitted`、销售订单的 `signed`） |
| 同一状态的词 | `approved`：「已批准」／「已通过」；`rejected`：「已驳回」／「已拒绝」；`submitted`：「已提交」／「待审批」 |
| 页面名称 | 菜单「项目」，页面标题「项目列表」；菜单「费用申请」，标题「我的费用申请」；菜单「企业连接」，标题「设置」 |
| 未保存 | 标题旁「未保存」；表单分区里「未保存修改 / 已保存」；Badge「尚未保存」 |
| 读取中 / 出错 | 转圈＋「正在读取最新数据…」；纯文字「正在读取…」「正在加载」；错误条；一行红字 |
| 查询栏控件 | 工时页用原生 `input/select`，其他页用 Fluent 控件；清除条件叫「清除筛选」或「清空条件」 |
| 时间 | ISO 原文 `2026-09-01T08:00:00Z`；`2026/9/1 16:00:00`；`16:00`；`2026-09-01` |
| 详情来源 | 「来源：ORYH · …」；「来源：ORYH 服务端 · 查询时间：…」 |

## 2. 同一件事只有一种说法

这些表达现在各自只存在一处：`packages/web/src/client/list-kit.tsx`。页面组合它们，不再自己写。

| 概念 | 统一表达 | 组件 |
| --- | --- | --- |
| 页首 | 标题；需要时标题旁一个状态胶囊、一句说明；右侧操作；页面的视图（如费用申请的「申请列表 / 本地草稿」）在标题下 | `PageHeader` |
| 打开一行 | 行尾“>”（屏幕阅读器读作「查看 X」）；首列标题链接同样可点 | `RowOpenHeader`、`RowOpenCell` |
| 返回 | 页首左上「← 返回列表」，详情页和表单页才有 | `BackToList` |
| 刷新 | 页首右侧「刷新」（图标＋文字），只在列表状态出现 | `RefreshButton` |
| 新建 | 页首右侧主按钮「＋ 新建…」 | `NewButton` |
| 清空条件 | 「清空条件」 | `ClearConditionsButton` |
| 状态 | 状态胶囊，列表和详情一致；等人处理的状态（已提交、待处理、待审批）用强调色 | `StatusPill` |
| 条数与分页 | 「共 N 条」＋「上一页 N / M 下一页」；在浏览器里过滤、且没有载入服务端全部记录时写「N 条（仅本次载入）」 | `ListFooter` |
| 空列表 | 有条件时「没有符合条件的记录」，没有条件时「当前没有记录」；可以换一句更具体的标题和下一步提示 | `EmptyState` |
| 读取中 | 转圈＋「正在读取…」 | `ListLoading` |
| 出错 | 错误条；读取失败可以直接重读时带「重新加载」，操作失败不带（是否重试由人决定） | `ErrorNote` |
| 时间 | 日期 `YYYY-MM-DD`，时刻 `YYYY-MM-DD HH:mm`，本地时间；不带时区的时间戳保留原钟面，不经 UTC 换算 | `formatDate`、`formatDateTime`、`formatDisplayValue` |
| 未保存 | 表单页首的状态胶囊「未保存」 | `StatusPill` |
| 详情来源 | 「来源：ORYH · 查询时间：…」 | — |

条数的统一不能以说错为代价。服务端分页的列表知道总数，写「共 N 条」；待办、费用、项目这类一次载入后在浏览器里过滤的列表，只有在载入了服务端全部记录时才写「共 N 条」，否则写「仅本次载入」。

## 3. 页面名称只有一个来源

`page-labels.ts` 规定每个内置页面叫什么，菜单、面包屑、页面标题都读它。由此：

- 「项目列表」→「项目」；「我的费用申请」「本地草稿」两个标题 →「费用申请」，两个视图作为标题下的切换；「设置」→「企业连接」。
- Host 向 agent 描述页面时读的是页面注册表（`@oryh/ai-client-pages` 的 `title`），它也改成与菜单一致（「项目」「Shipment · 收发货」），否则用户看到「项目」、agent 却说「项目列表」。`page-labels.spec.ts` 保证两边一致。
- 用户自建的菜单项（docs/24）是数据，名称由用户决定，不经过这张表。

## 4. 状态词

ORYH 的状态名是租户的词汇：租户可以改名、增加状态，状态机本身不带显示文字（calwbiz `app/services/state_machines.py` 关于 `roles` 的说明）。所以客户端不能自称掌握完整的状态词表。`status-words.ts` 的做法是：

- 只翻译 ORYH 默认状态机里、本客户端会显示到的状态名；不认识的状态原样显示，不借用别的状态的意思。
- 原来两张互相矛盾的对照表合并为一张。词与审批人看到的按钮一致（通过 / 拒绝 / 退回修改）：`approved` 已通过、`rejected` 已拒绝、`returned` 已退回；`submitted` 统一为「已提交」。
- 「工时审批」队列里的「待审批」不是状态翻译：队列中每一行都在等你审批，它说的是这个含义。

尚未处理、需要 ORYH 提供显示名的：库存流水「变动原因」（`received` 等）、销售订单「订单类型」（`order`）、收发货「方向」（`inbound` / `outbound`）目前显示英文原值。ORYH 的 `/type-options` 没有这几个族，客户端不应自行编一套。

## 5. 有意保留的差异

- **服务端查询与页内筛选。** 销售订单、库存、收发货的查询条件发给服务端，需要按「查询」；待办、费用、项目、工时是对已载入记录的即时筛选，输入即生效。行为不同，控件就不同；条数写法（「共 N 条」／「仅本次载入」）说明了是哪一种。
- **表单内的保存反馈**（工时单保存栏、项目表单底部）仍就地显示在保存按钮旁，因为它说的是这次保存，而不是整页。

## 6. 防止回退

- `list-kit.spec.ts` 扫描客户端所有 `.tsx`，发现手写的空态、页脚、分页、读取中、页首、状态胶囊，Fluent `Badge`，刷新 / 返回 / 翻页图标，「打开」「查看」按钮文字，“←”字符，`toLocale*String()`，就失败，并指出应该用哪个组件。
- `page-labels.spec.ts` 保证 agent 与菜单对同一页面用同一个名字。
- 新页面需要一种新的共享表达时，加到 `list-kit.tsx`，不要在页面里就地写。

## 7. 验证

- 全部包构建、类型检查通过；测试全部通过（web 41、dsh-host 62、core 86、records 22 等共 250 项）。
- 在运行中的客户端逐一核对 11 个菜单入口（含用户自建的「入库单」）的页面结构：面包屑、标题、菜单名三者一致；列表页首操作、行尾“>”、页脚条数与翻页、状态胶囊、时间格式一致。另查看了工时详情、销售订单详情、新建工时单、新建项目、费用本地草稿，浅色与深色均正常。
