# 费用申请的传统操作流程

实施日期：2026-09-08。当前实现提供本地表单、费用明细、票据上传、校验、创建、提交与结果核对，不调用模型。AI 将来只能复用同一草稿和受限业务能力；确认创建与正式提交保留为用户界面动作。

## 用户流程

1. 连接 ORYH 后，在“费用申请”中选择新建，填写标题、日期、币种和明细。费用类别读取当前企业的 active expense_category，不固定为全局枚举。
2. 随时保存本地草稿，包括尚未填完的草稿。金额最多两位小数，合计以分计算；必填项未齐不能进入在线校验。未保存修改或正在执行费用请求时，企业切换和断开入口暂停，离开页面会提示未保存内容。
3. 每条明细可选择 PDF、PNG 或 JPEG 票据，当前上限为 500 KB。选中文件会立即上传到当前企业，服务端按内容摘要去重。附件回执校验 SHA-256；只有同一身份下已上传或已保存的回执可绑定到草稿。去掉明细或归档草稿不删除已上传的服务端附件。
4. 选择“服务端校验并准备创建”。只有服务端明确返回 `validate_only: true, written: false` 才展示创建确认。dry-run 返回的临时 id 不当作真实记录。
5. 创建确认展示当前企业、账号、标题、日期、币种、合计、全部明细和附件名称。确认只适用于当前草稿版本，五分钟后过期；修改草稿会使旧确认失效。
6. 确认创建后显示 ORYH 记录编号和真实状态。创建与提交分开；提交前重新读取详情并核对本地字段，再显示正式提交确认。当前版本中，创建后的内容修改需进入该记录的 ORYH Console 页面。
7. 提交回执必须包含匹配的记录和员工以及 submitted_at。UI 展示真实状态，不把提交描述为审批通过或付款。
8. 网络断开、错误响应或进程中断后，记录可能进入“结果待核对”。点击核对会读取服务端事实，绝不自动重放创建。不能唯一匹配时保持待核对状态，并要求在 ORYH 查看实际记录。

## 身份、确认和恢复

草稿绑定 `origin + tenant + user + employee`，不依赖可能在重启后复用的本地连接序号。列表、保存、准备、确认、核对与附件上传都要求已验证的连接；准备与确认还会重新执行 `/auth/me`。员工字段与目标企业来自 Host，不接受表单或未来模型覆盖。费用类别、重复票据、业务状态、权限和员工归属最终由 ORYH API 检查。

`ExpenseService` 只接受规范字段，不透传客户端提供的 status、employee_id 或其他任意请求字段。确认令牌绑定在加密保存的记录版本上，确认请求不重新携带可替换的业务参数；同版本只有一次追加成功的请求可以进入写入。

每次写入前，先持久记录 creating/submitting，再发 HTTP 请求。费用 POST 禁止传输层自动重放。重启读取到中间状态时显示结果未知。创建请求在 custom_fields 中附加 `oryh_client_draft_id`，核对按员工分页查找该标识，并验证记录归属和明细；最多扫描 20 页，每页请求 100 条。超出范围、分页信息缺失、没有匹配、存在多个匹配或字段不同，都不能认定创建失败或安全重试。

提交核对读取已知 claimId 的详情，依据 submitted_at 和服务端状态显示结果。客户端不硬编码租户的 draft/submitted 状态名称，不决定审批或后续流程。

## 本地存储

本地 Web Host 使用 `EncryptedExpenseStore`，目录为应用数据目录下的 expenses。快照使用 AES-256-GCM 加密；加密密钥单独存在 OS Keychain，以数据目录摘要区分账号。每个草稿的版本为只追加文件，独占创建避免两个客户端进程提交同一版本。文件及目录同步完成后才允许远端写入。

最新版本损坏或无法解密时停止读取和写入，不能回退到仍可执行的旧确认。归档只隐藏本机列表中的记录，保留加密版本用于核对；不会删除真实申请或附件。断开连接保留加密费用记录，重新连接相同企业、用户与员工后可恢复。彻底删除历史数据和可配置保留期限尚未提供。

单元测试使用 MemoryExpenseStore 或注入测试密钥的加密存储。生产本地 Web 使用系统钥匙串，不把密钥写到文件。DSH 开发 bundle 尚未装配此费用服务，不能据此声称 DSH Agent 已具备写入能力。

## 接口与验证

浏览器通过 `/api/client/expenses/{list,options,save,prepare,confirm,reconcile,upload,archive}` 的同源 POST 调用。Host、Origin、JSON 类型、请求大小和连接标识由现有本地 API 边界检查，业务字段及版本在 ExpenseService 再校验。

已覆盖正常创建/提交、dry-run 回执检查、修改/过期确认、并发重复确认、加密版本竞争、损坏日志、跨身份访问、附件回执、回执丢失后的服务重建与恢复，以及模糊匹配拒绝。浏览器验证使用模拟企业、合成票据和真实 Chrome，完成整个表单到提交链路，并检查 390px 布局无水平溢出。

本轮 `corepack pnpm run verify` 通过类型检查、58 项测试和构建；浏览器验证记录了一次创建与一次提交，校验阶段零创建，页面运行错误为零。

当前验证没有登录远端测试环境或创建真实单据，也未验证 Windows/Linux 原生钥匙串及文件同步行为。部署前需要核实实际 ORYH 版本支持 validate_only、附件摘要去重和当前字段契约。

## 仍需演进的保障

- 服务端创建尚无通用幂等键；客户端日志能防止本地同版本重放，不能提供跨设备的业务去重保证，也不能用一次扫描未命中证明请求未成功。
- 提交前的详情摘要检查能发现已经发生的修改，但 ORYH submit 尚不接受原子版本条件；详情读取与提交之间的外部并发修改仍需要服务端版本校验解决。
- 初版不支持税额、项目/供应商关联、企业自定义字段编辑、大附件、服务端草稿原位编辑或正式审批。
- 系统用户在场验证、窗口会话认证、受管模型、AI 材料识别和生产 DSH Profile 尚未完成。本轮不能作为完整生产客户端发布。
